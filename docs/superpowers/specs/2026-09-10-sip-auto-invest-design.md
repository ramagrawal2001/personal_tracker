# SIP Auto-Invest & Recurring Surfacing — Design

**Date:** 2026-09-10
**Status:** Approved (approach A; per-section review waived — "build everything and then test")
**Branch:** `feat/sip-auto-invest`

## Goal

Give SIP investments the same "recurring, scheduled" treatment loan EMIs already
have, plus a genuinely new capability the app has never had — **auto-posting**
the SIP transaction on its `sipDay`:

1. **SIP due reminders** — a block in `PaymentReminders.compute` mirroring the
   Loans (EMI) block, for every investment with `monthlySipAmount > 0`.
2. **Dashboard "Upcoming SIPs" tile** — next to "Upcoming EMIs", using the
   existing `FinanceState.totalMonthlySipAmount`.
3. **SIPs in the Financial Calendar** — SIP occurrences appear as dots and as
   rows in the obligations list, via a new merged `FinanceState.upcomingObligations`.
4. **Auto-post** — a per-investment "Auto-invest on SIP day" toggle. When on,
   the app posts the SIP investment transaction once per month, on/after
   `sipDay`, from a single user-chosen account.

## Decisions (from brainstorming)

- **Auto-post trigger:** per-investment toggle (`auto_invest_enabled`). Off by
  default. This toggle *is* the "recurring option like the EMIs" the request
  named. Reminders and the calendar show all SIPs regardless of the toggle.
- **SIP debit account:** one global setting, stored **device-local in
  SharedPreferences** (`finance_sip_debit_account_id`), surfaced as a dropdown
  in Settings. Device-local is deliberate: auto-post is a device-initiated
  catch-up, and the sync'd idempotency marker (below) already prevents a second
  device from double-posting. `null` ⇒ auto-post is inert.
- **Catch-up:** current calendar month only. At most one auto-post per
  investment per month; no backfill of missed months.
- **Safe-to-Spend:** SIP outflows do **not** reduce Safe-to-Spend — same as
  EMIs (separate tile, never folded into `upcomingPaymentsTotal`).

## Non-goals

- Auto-advancing / auto-posting ordinary `RecurringPaymentModel`s (out of scope;
  this is SIP-only).
- Backfilling missed SIP months.
- EMIs in the calendar (only SIPs are added there now).
- A per-investment debit account (one global account for v1).

## Section 1 — Schema changes

### `investments` (Drift + Supabase + model + mapper)

| Column | Type | Default | Meaning |
|---|---|---|---|
| `auto_invest_enabled` | bool | `false` | The "Auto-invest on SIP day" toggle. |
| `last_auto_posted_month` | text, nullable | `null` | `"YYYY-MM"` of the last auto-post. Idempotency marker; syncs across devices. |

- **Drift** (`lib/core/database/tables.dart`, `Investments`): add
  `BoolColumn get autoInvestEnabled => boolean().withDefault(const Constant(false))();`
  and `TextColumn get lastAutoPostedMonth => text().nullable()();`.
- **`schemaVersion`** in `lib/core/database/app_database.dart`: `8 → 9`, with a
  `if (from < 9)` block using the file's existing defensive
  `addColumnIfMissing` pattern for both columns.
- **`InvestmentModel`** (`lib/domain/models/models.dart`): two new final fields
  (`bool autoInvestEnabled = false`, `String? lastAutoPostedMonth`), constructor
  params, and `copyWith` params.
- **`finance_mappers.dart`**: `InvestmentEntryMapper.toModel()` reads them;
  `InvestmentModelMapper.toCompanion()` writes them.
- **`cloud_mappers.dart`** `InvestmentCloud`: `toCloudJson` emits
  `'auto_invest_enabled'` and `'last_auto_posted_month'`; `fromCloud` reads
  `_bool(m['auto_invest_enabled'])` and `m['last_auto_posted_month'] as String?`.
- **`app_database.g.dart`**: regenerated by
  `dart run build_runner build --delete-conflicting-outputs`.

### Supabase migration `supabase/migrations/0008_sip_autopost.sql`

```sql
alter table public.investments
  add column if not exists auto_invest_enabled boolean not null default false,
  add column if not exists last_auto_posted_month text;
```

(No new RLS/trigger/index needed — `investments` already has them.)

### SharedPreferences

- New key constant `kPrefSipDebitAccount = 'finance_sip_debit_account_id'` in
  `cloud_mappers.dart` (alongside the other `kPref*`).
- Read on `FinanceNotifier` load into a new `FinanceState.sipDebitAccountId`
  (`String?`), written by a new `setSipDebitAccount(String? accountId)` mutator
  (prefs-only; no cloud push). Mirrors how `biometricEnabled` stays local.

### Backward compatibility

All columns nullable/defaulted; `fromCloud`/`toModel` default-guard. An older
app build ignores the new columns. A `0008`-less Supabase project still works
(the client tolerates missing columns on read).

## Section 2 — Auto-post runner

New on `FinanceNotifier`:

```dart
/// Posts this month's SIP for every enabled investment whose sipDay has
/// arrived and that has not been auto-posted this month. Idempotent, safe to
/// call repeatedly. No-op when no debit account is configured.
Future<void> processDueSipAutoPosts([DateTime? clock]) async { ... }
```

### Algorithm

```
now        = clock ?? DateTime.now()
monthKey   = "${now.year}-${now.month.toString().padLeft(2,'0')}"
accountId  = state.sipDebitAccountId
if accountId == null: return
if state.accounts.every((a) => a.id != accountId || a.isDeleted): return   // stale setting
if _sipAutoPostRunning: return
_sipAutoPostRunning = true
try:
  for inv in state.investments where !isDeleted && autoInvestEnabled && monthlySipAmount > 0:
    if inv.lastAutoPostedMonth == monthKey: continue
    lastDay = DateTime(now.year, now.month + 1, 0).day
    sipDate = DateTime(now.year, now.month, inv.sipDay.clamp(1, lastDay))
    if now.isBefore(sipDate): continue                                     // not due yet
    // ledger backstop: skip if a sip-auto txn for this inv already exists this month
    if state.transactions.any((t) => !t.isDeleted
         && t.type == TransactionType.investment
         && t.investmentId == inv.id
         && t.tags.contains('sip-auto')
         && t.date.year == now.year && t.date.month == now.month): 
      // recover the missed marker, then move on
      await updateInvestment(inv.id, lastAutoPostedMonth: monthKey)
      continue
    try:
      await addTransaction(
        type: TransactionType.investment,
        amount: inv.monthlySipAmount,
        accountId: accountId,
        investmentId: inv.id,
        date: sipDate,
        description: 'Auto SIP — ${inv.name}',
        tags: ['sip-auto'],
      )
      await updateInvestment(inv.id, lastAutoPostedMonth: monthKey)
    catch e:
      debugPrint('SIP auto-post failed for ${inv.id}: $e')   // offline etc. — retry next open
finally:
  _sipAutoPostRunning = false
```

- **Reuses `addTransaction(type: investment, investmentId:)`** — which already
  bumps `investedAmount` + `currentValue` and debits the account (balance calc
  treats `investment` as a debit). No new ledger logic.
- **`updateInvestment` gains two params:** `int? sipDay`, `bool?
  autoInvestEnabled`, `String? lastAutoPostedMonth` (all pass straight into
  `copyWith`). `sipDay` is added now because the edit sheet needs it too
  (Section 4).
- **Idempotency:** primary = `last_auto_posted_month == monthKey` (synced, so a
  second device skips). Backstop = ledger scan for a `sip-auto`-tagged txn this
  month, which recovers from a crash between `addTransaction` and the marker
  write. Deleting the auto-posted transaction does **not** cause a re-post
  (month already marked) — intentional.
- **Offline:** `addTransaction` pushes to cloud first; a real-offline throw is
  caught per-investment, the month is left unmarked, and the next call retries.
  Demo accounts (`pushToCloud` returns null) post local-only, fine.

### Where it runs

- `FinanceNotifier` constructor / first load: after `_loadFromDb()` populates
  `state`, `unawaited(processDueSipAutoPosts())`.
- `MainShell.didChangeAppLifecycleState(resumed)`: it already calls
  `refreshFromCloud()`; chain `.then((_) => ...processDueSipAutoPosts())` so a
  device that was open across midnight into `sipDay` still posts.

## Section 3 — SIP reminders

New block in `PaymentReminders.compute`, after the Loans (EMI) block, mirroring
it. `_Kind` reused (`dueSoon`, `dueToday`). Entity id namespaced `sip_<id>` so
it can never collide with a loan/card/recurring id in `idFor`.

```dart
// ── SIPs ────────────────────────────────────────────────────────────
for (final inv in state.investments) {
  if (inv.isDeleted) continue;
  if (inv.monthlySipAmount <= 0) continue;
  final due = inv.sipDay.clamp(1, 31);
  final dueDate = nextOnDay(due, now, _dueHour);
  final soon = dueDate.subtract(const Duration(days: _daysBefore)).copyWithHour(_reminderHour);
  final auto = inv.autoInvestEnabled;
  if (soon.isAfter(now)) {
    out.add(ReminderSpec(
      id: idFor('sip_${inv.id}', _Kind.dueSoon.index),
      when: soon,
      title: auto ? '🔁 ${inv.name} SIP auto-invests soon' : '${inv.name} SIP due soon',
      body: auto
          ? '${_amt(inv.monthlySipAmount)} will be invested in $_daysBefore days.'
          : '${_amt(inv.monthlySipAmount)} SIP due in $_daysBefore days.',
    ));
  }
  out.add(ReminderSpec(
    id: idFor('sip_${inv.id}', _Kind.dueToday.index),
    when: dueDate,
    title: auto ? '🔁 ${inv.name} SIP auto-invests today' : '${inv.name} SIP due today',
    body: auto
        ? 'Investing ${_amt(inv.monthlySipAmount)} automatically.'
        : 'Invest ${_amt(inv.monthlySipAmount)} — log it in Investments.',
  ));
}
```

### Scheduler signature

`financeNotifierProvider`'s `onStateChanged` signature string (currently cards +
loans + recurring) gains a SIP line so a `sipDay` / `monthlySipAmount` /
`autoInvestEnabled` edit reschedules:

```dart
for (final i in s.investments)
  if (!i.isDeleted && i.monthlySipAmount > 0)
    'S${i.id}:${i.sipDay}:${i.monthlySipAmount}:${i.autoInvestEnabled}',
```

## Section 4 — Calendar & dashboard & modal

### `FinanceState.upcomingObligations`

New getter returning a merged, date-sorted list the calendar consumes:

```dart
enum ObligationKind { recurring, sip }

class UpcomingObligation {
  final String id;          // recurring payment id, or 'sip_<investmentId>'
  final String sourceId;    // the underlying recurring/investment id
  final ObligationKind kind;
  final String title;
  final double amount;
  final DateTime date;      // this cycle's due date
  final bool isIncome;      // always false for sip
}

List<UpcomingObligation> upcomingObligations(DateTime monthAnchor) { ... }
```

- Recurring items: one entry per non-deleted `RecurringPaymentModel` at its
  `nextDueDate` (unchanged semantics; `isIncome` carried through).
- SIP items: one entry per non-deleted investment with `monthlySipAmount > 0`,
  dated at this month's `sipDay` (clamped to month length), `isIncome: false`,
  `title: '${inv.name} SIP'`.

### `calendar_screen.dart` refactor

- Replace the three `recurringPayments`-derived local lists (`dueDays`,
  `incomeDays`, `upcoming`/`future`) with values derived from
  `financeState.upcomingObligations(_focusedMonth)`.
- Dot rendering, "N payments due" chip, and the obligations `ListView` switch to
  `UpcomingObligation`.
- Row `onTap`: `kind == recurring` → existing `_showRecurringSheet(existing:)`;
  `kind == sip` → `context.push('/investments')`.
- The "+" FAB still adds a `RecurringPaymentModel` only (unchanged).

### Dashboard — `money_summary_card.dart`

- Add `final double upcomingSips;` (required) to `MoneySummaryCard`.
- Restructure the single 3-tile `Row` (Bank Balance / Card Due / Upcoming EMIs)
  into a 2×2: row 1 Bank Balance / Card Due, row 2 Upcoming EMIs / **Upcoming
  SIPs** (icon `LucideIcons.repeat`, colour `AppColors.transfer`).
- `dashboard_screen.dart`: pass `upcomingSips: financeState.totalMonthlySipAmount`
  at both call sites (large + small screen).

### Add / Edit Investment UI

- **`add_investment_modal.dart`**: below the SIP Day field, a
  `SwitchListTile` "Auto-invest on SIP day" (default off), enabled only when the
  SIP amount field is > 0. Pass `autoInvestEnabled:` into `addInvestment(...)`.
- **`addInvestment(...)`** gains `bool autoInvestEnabled = false`.
- **Investments edit sheet** (`investments_screen.dart`, "Update Value" /
  "Update Investment"): add a "SIP Day" number field and the same
  "Auto-invest on SIP day" switch; pass `sipDay:` and `autoInvestEnabled:` into
  `updateInvestment(...)`.
- **Settings screen**: a "SIP debit account" dropdown (list of active
  liquid accounts + a "None" option) bound to `state.sipDebitAccountId` /
  `setSipDebitAccount(...)`. Shown in the section with the emergency-buffer /
  currency settings. If a user enables auto-invest on any investment while this
  is unset, show an inline hint linking to the setting.

## Section 5 — Edge cases & failure modes

| Case | Behaviour |
|---|---|
| No debit account configured | `processDueSipAutoPosts` returns immediately. Reminders/calendar still work. Investment edit shows a hint. |
| Debit account later deleted | Runner detects the id is absent/deleted and returns without posting. |
| App opened many months later | Only the current month posts (one entry). `last_auto_posted_month` jumps straight to now; missed months are not backfilled. |
| Two devices, same account | Whichever runs first posts and sets `last_auto_posted_month`; it syncs; the other device sees `== monthKey` and skips. |
| Crash between `addTransaction` and marker write | Next run's ledger backstop finds the `sip-auto` txn for the month, writes the missing marker, does not double-post. |
| User deletes the auto-posted transaction | No re-post (month is marked). `currentValue` / `investedAmount` are adjusted by the existing `deleteTransaction` investment side-effect. |
| Offline (real Supabase session, no network) | `addTransaction` throws; caught per-investment; month left unmarked; retried on next open/resume. |
| `sipDay` = 31 in a 30-day month | Clamped to the last day of the month (matches `PaymentReminders.nextOnDay`). |
| `monthlySipAmount` set to 0 after enabling | Runner skips (`> 0` guard); reminder block skips; calendar entry drops. Toggle value is retained but inert. |
| `flutter test` / web | `NotificationService` no-ops (existing). `processDueSipAutoPosts` runs against in-memory state; with no `sipDebitAccountId` set in a test it no-ops unless the test sets one. |

## Section 6 — Testing

### Unit (`flutter test`)

- **`test/payment_reminders_test.dart`** (extend): SIP block emits `dueSoon` +
  `dueToday` with correct dates/ids; auto-on vs auto-off wording; skipped when
  `monthlySipAmount == 0` or `isDeleted`; `sip_<id>` ids don't collide with a
  loan sharing timing.
- **`test/sip_auto_post_test.dart`** (new): drive `FinanceNotifier` with an
  in-memory `AppDatabase`:
  - posts once when `sipDay` has passed, `autoInvestEnabled`, account set;
  - does nothing before `sipDay`, when disabled, when `amount == 0`, when no
    account, when account deleted;
  - second call same month is a no-op (marker);
  - ledger-backstop: pre-insert a `sip-auto` txn with no marker → marker gets
    written, no second txn;
  - posted txn debits the chosen account and raises `currentValue` by the SIP
    amount (via the existing side-effect);
  - `clock` param controls "now".
- **`test/upcoming_obligations_test.dart`** (new): merge + sort of recurring and
  SIP entries; SIP date clamped; income flag; deleted/zero-amount excluded.
- **`test/migration_check_test.dart`**: passes with `schemaVersion` 9 (the
  file's synthetic-upgrade harness already covers defensive `addColumn`).

### Manual (iOS simulator, demo account)

1. Investments → add a SIP fund, amount ₹5,000, SIP Day = today or earlier,
   toggle **Auto-invest on** → save.
2. Settings → set SIP debit account to HDFC Savings.
3. Force-quit + relaunch (or background/foreground) → a ₹5,000 "Auto SIP" expense
   appears on HDFC Savings dated the SIP day; portfolio invested/current +₹5,000;
   Dashboard "Upcoming SIPs" shows ₹5,000; Calendar shows a dot + row on the SIP
   day; relaunch again → no second post.
4. Toggle auto-invest **off**, bump SIP day to a future date, relaunch → no post;
   reminder wording is "SIP due" not "auto-invests".
5. `flutter analyze` clean.
